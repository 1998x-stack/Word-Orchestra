## Confirmed repository baseline (2026-11-17)

- The repository began as a product-specification bootstrap; there was no application code, package manager, runtime, or test suite at the start of implementation.
- The default branch is main. Product design source is docs/Word-Orchestra-Product-Design.md; Word/PDF artifacts are generated by .github/workflows/build-docs.yml.
- The document workflow currently runs on pushes to main that touch docs/*-Product-Design.md or the workflow itself. Architecture documents do not need to regenerate the Word/PDF artifacts.
- No PRs or issues were open at the time the engineering branch was created.

## Design constraints to preserve

- Copy is typing practice, not evidence of vocabulary mastery.
- Recall after answer reveal is not successful retrieval.
- Never add a global keyboard listener for the practice experience.
- Never persist arbitrary raw typed text in composition records.
- Do not claim that Web Audio oscillators reproduce a real piano.
- Do not add audio assets without source, license, and attribution metadata.

## Known implementation constraints

- The starter vocabulary contains 12 hand-authored examples and is only a prototype seed, not a frequency-ranked or licensed dictionary corpus.
- The first synthesizer uses a triangle oscillator. It is not a sampled piano and must not be marketed as one.
- Direct package versions are pinned in package.json, but package-lock.json is not yet committed. Generate and commit it before merging; until then CI uses npm install rather than npm ci.
- Browser-specific Web Audio latency and IndexedDB behavior still require real-browser verification.
- Composition replay is based on recorded note events; it is not yet a polished arrangement engine with harmonic progression or phrase-aware rests.

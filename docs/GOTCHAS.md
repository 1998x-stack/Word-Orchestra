# Word Orchestra — Engineering Gotchas

This is the operational handoff for future agents and contributors. Add a dated entry whenever a real defect, environment trap, or non-obvious constraint is discovered. Do not record hypothetical issues as confirmed bugs.

## Confirmed repository baseline (2026-11-17)

- The repository began as a product-specification bootstrap; no application runtime or test suite existed before Phase 0.
- The default branch is main. The product design source is docs/Word-Orchestra-Product-Design.md; Word/PDF artifacts are generated by .github/workflows/build-docs.yml.
- Architecture and first runnable practice branch are feat/architecture-and-phase0, PR #1.

## Design constraints to preserve

- Copy is typing practice, not evidence of vocabulary mastery.
- Recall after answer reveal is not successful retrieval.
- Never add a global keyboard listener for the practice experience.
- Never persist arbitrary raw typed text in composition records.
- Do not claim Web Audio oscillators reproduce a real piano.
- Do not add audio assets without source, license, and attribution metadata.

## Confirmed defects and mitigation

### 2026-11-17 — Navigation unmounted an active practice session

- **Symptom:** Switching from practice to progress and back discarded unsaved input and session state.
- **Root cause:** App conditionally rendered one screen at a time.
- **Fix:** Keep the active practice component mounted when switching tabs, with a hidden wrapper.
- **Regression test:** Browser E2E checks that a draft survives tab switches.
- **Validation:** Unit CI PASS at 7f16f37; browser E2E is pending.

### 2026-11-18 — App-level audio lifetime boundary

- **Symptom:** PracticeScreen directly constructed a browser audio adapter, making integration tests and dependency boundaries harder to verify.
- **Root cause:** Adapter instantiation inside a presentation feature.
- **Fix:** Construct and own the WebAudioEngine in the application composition root, inject its port into PracticeScreen.
- **Validation:** CI PASS at 7af7121.

## Known implementation limitations

- The starter vocabulary contains 12 hand-authored examples, not a fully verified frequency-ranked or licensed dictionary pack.
- The synthesizer uses a triangle oscillator and does not reproduce a sampled piano.
- Composition replay stores ordered note events; it is not yet a phrase-aware harmonic arrangement engine.
- Soft time offsets on character notes are generated by a simple bounded spacing algorithm; this needs future timing model refinements.
- Current progress aggregates attempts; later phases must add sense/direction-aware evidence and durable content provenance.
- Browser automation tests are not a substitute for real Safari and physical audio latency measurements.

### 2026-11-18 — Playwright 1.56.1 unsupported on ubuntu-26.04 runner

- **Symptom:** All 17 Vitest tests, lint, typecheck, and production build passed, but Playwright browser install failed before E2E execution.
- **Root cause:** GitHub's ubuntu-latest resolved to Ubuntu 26.04, while this pinned Playwright version does not support that OS.
- **Reproduction:** Run `npx playwright install --with-deps chromium firefox webkit` on ubuntu-26.04-x64; error reports unsupported platform.
- **Fix:** Pin the browser CI runner to ubuntu-24.04, an explicitly supported OS for Playwright 1.56.
- **Regression test:** Full browser E2E must complete on the pinned runner.
- **Validation:** Initial run FAILED at browser installation; rerun pending.
